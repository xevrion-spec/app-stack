# ADR 0027 — Practice integrations: interfaces, mappers, mock adapters, contract tests

Status: accepted (2026-10-25). No network calls anywhere; synthetic fixtures only.

| Integration                                 | What is real                                                                                                                                                                                                         | What is mock / missing                                                                                                                       |
| ------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------- |
| Xero / QuickBooks Online / FreeAgent (read) | Field mappers (dates incl. Xero `/Date()/`, signs, VAT codes), account-name → chart mapping with a reason, `LedgerReadAdapter` interface, per-client sync through the real ingest + dedupe + categorisation pipeline | Adapters return fixture data. Live use needs OAuth apps (Xero, Intuit, FreeAgent) and verification of raw shapes against real tenants        |
| File imports                                | Bank CSV/OFX/QIF/MT940, Xero/QuickBooks/FreshBooks CSV and (new) **FreeAgent** CSV exports                                                                                                                           | —                                                                                                                                            |
| Practice management (Karbon/XPM-style)      | `PracticeManagementAdapter` interface + idempotent mock                                                                                                                                                              | No provider chosen                                                                                                                           |
| E-signature                                 | `ESignAdapter` envelope lifecycle + mock. In-portal acceptance by hash (M3) is real                                                                                                                                  | No provider chosen                                                                                                                           |
| MTD VAT submission                          | 9-box arithmetic validation, legal-declaration gate, fraud-prevention header builder, sandbox config (no credentials)                                                                                                | `MockHmrcVatAdapter` only. HMRC is never called. Needs HMRC developer registration, production approval/recognition, fraud-header validation |
| Open Banking (AISP)                         | `OpenBankingProvider` consent lifecycle (authorise, 90-day expiry, revoke)                                                                                                                                           | `MockOpenBanking` only. Needs an FCA-authorised AISP partner                                                                                 |

- **Contract tests** (`packages/books/test/integrations.contract.test.ts`) define what any adapter must satisfy: integer pence, ISO
  dates, unique ids, sorted, range-respecting, idempotent. A live adapter is added to the same `describe.each` list.
- **Event:** `integration.synced` (v1).
- **Catalogue:** `GET /v1/practice/integrations` reports each integration as `real`, `mock` or `interface`. Keep it honest;
  the benchmark reads from it.
